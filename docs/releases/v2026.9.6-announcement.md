# v2026.9.6 Release Announcement

Fortemi v2026.9.6 improves recovery and startup during upgrades from older databases.

Bundle startup waits up to two hours by default for the API to become ready, while checking that the process remains alive and reporting progress. The wait is configurable. MCP registration begins after API readiness. Temporary API outages keep the saved MCP registration intact, and unexpected registration responses produce a diagnostic instead of terminating startup.

Repeated upgrade attempts can reuse a recent verified recovery point when its database state, migration identity and artifact integrity still match. Changed data, schema, sequences, migration progress or target invalidate reuse. Verification metadata is published atomically, and failed replacements preserve the previous recovery artifact. Reuse does not freeze database writes or guarantee eligibility after a partially completed migration.

The release also repairs the missing tenant-qualified note key in legacy archive schemas before the source-addressed migration needs it. Published migration SQL remains unchanged. An expanded February-baseline upgrade with 102,000 notes passed and its pre-migration backup restored the recorded counts and relationships. A subsequent validation-only refactor passed separate small-upgrade and real-PostgreSQL regressions.

For constrained CPU installations, follow the updated February-to-current upgrade runbook and its optional-sidecar memory-headroom guidance. The two-hour default is a configurable limit, not a promised upgrade duration. The customer-reported Windows timing has not been independently reproduced.

Before release completion, the configured CI, published artifacts and isolated bundle startup/recovery checks must pass. This maintenance release adds no unqualified suite parity, complete-backup or universal-portability claim. Knowledge Shard guarantees remain limited to named profiles and their executable evidence.
