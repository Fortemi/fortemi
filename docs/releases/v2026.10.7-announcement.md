# Fortémi 2026.10.7

2026.10.7 improves search precision, archive-ingestion dependency posture,
release-validation controls, and OIDC authorization audit attribution.

## What changed since 2026.10.6

- **Adaptive keyword search.** Plain-language keyword searches begin with
  strict matching and use a bounded OR expansion only when results are scarce
  or the query is long. Explicit Boolean syntax remains strict. Deterministic
  relevance baselines are now gated in CI (#1209, #1210, #1223, #1224).
- **Archive ingestion and builder hardening.** Archive ingestion moves to
  `zip` 9 with narrowly scoped dependency exceptions. The builder uses patched
  Docker CLI and Buildx versions. The Docker-socket-bearing `ops-autoheal`
  profile is disabled pending a reviewed replacement (#1221, #1233, #1237,
  #1240, #1241).
- **Safer release validation.** CI resources and concurrency are scoped to each
  run. Pull requests receive change-scoped testing, while main and release
  candidates require their respective post-merge and exact-source validation
  paths (#1234, #1246, #1248, #1249, #1250, #1252).
- **OIDC audit attribution.** Authorization decision audits retain the verified
  authorized-party claim, and delegated event tokens retain their minting-client
  attribution (#1206, #1225, #1253).

## Upgrade notes

The `ops-autoheal` profile is disabled because its containers hold the Docker
socket. The operator guide documents the retirement procedure for affected
deployments. Other deployments have no release-specific data migration.

## Integration status

This release does not change the suite's NO-GO status or claim unqualified
Knowledge Shard portability. Profile boundaries remain explicit: any
`core-v1`, `full-v1`, or `record-v1` use remains subject to its applicable
contract and acceptance matrix. W01a integration acceptance remains pending
after this release; publication is not evidence of that acceptance.

## Verification boundaries

Publication is gated on exact-source main validation, the comprehensive test
handoff, the docsite build, a signed release tag, and tag-triggered publication
verification. These gates do not substitute for the separate integration
acceptance described above.
