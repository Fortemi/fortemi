# Fortemi 2026.9.10

This release corrects scoped Knowledge Shard restoration and native tenant
membership. It also supplies producer-owned read/mutation fixtures for the React
remote adapter and strengthens fresh-database CI validation.

The versioned lifecycle-purge authority adds bounded previews, atomic relational
erasure, resumable blob and search cleanup, content-free terminal receipts, and
restore-time re-erasure. Deployment approval and retention policy remain
operator responsibilities; this release does not assert complete backup or
unqualified erasure coverage outside the recorded purge contract.

Validated restore preserves schema-valid tag strings without running the live
authoring tag grammar. Scoped schema-2 `full-v1` replacement retains existing
record identities, unselected children and independent graph, taxonomy and
provenance roots. Selected records can exchange supported unique coordinates
without deleting retained identities; collisions with unselected owners and
remaining invalid references reject transactionally.

Archive-local configuration declarations and explicit bootstrap custody prevent
restore cleanup from removing sibling archive or shared native state. Native
authoring side effects are suppressed only while applying validated restoration.
SKOS final-state constraints and tenant/archive writer coordination cover the
tested cycle, depth and cardinality cases without relaxing ordinary guards.

Automatic embedding memberships now use the triggering note's tenant and schema
for selection, criteria and insertion. Archive-qualified writes no longer consult
public sets, and foreign tenant sets are excluded even on privileged connections.
RLS, tenant-qualified foreign keys, tombstone and import suppression remain.

Upgrade through the normal migration runner to apply the 21 new forward
migrations after 2026.9.9. Applied migration files are unchanged. Preserve a
verified pre-upgrade backup; an older binary alone is not a database rollback.
No existing memberships are backfilled by the tenant correction.

Knowledge Shard schema/profile authorities and live API contracts are unchanged.
Historical matrix receipts keep their exact profile, source and platform scope.
The new native behavior still requires coordinated acceptance against actual
released producer and consumer artifacts, including the remaining authenticated,
worker and platform cells. The suite remains NO-GO for unqualified portability,
full parity or complete backup; this release does not close Lane B acceptance.

Standard public builds retain their existing feature profiles. OpenBao Transit
continues to require the separately configured internal `kms-vault` build and
its own deployment qualification. Publication is complete only after container,
comprehensive-test, native-binary, release-asset and mirror verification passes.
