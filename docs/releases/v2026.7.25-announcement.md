# v2026.7.25 Release Announcement

Fortemi v2026.7.25 is the corrective publication for v2026.7.24. The signed
v2026.7.24 tag published native sidecar assets, but its hosted container build
exhausted the 32 MiB rustc worker stack and did not pass the release gate. It
should not be deployed as a completed release.

The corrected release raises the Rust 1.92 release-build worker stack to the
exact 64 MiB requirement reported by the hosted runner. The application
behavior, six forward migrations, and `core-v1` Knowledge Shard application
contract are otherwise unchanged from v2026.7.24.

## Fixed

- Semantic chunking preserves exact UTF-8 byte spans across LF, CRLF,
  lone-CR, mixed line endings, and non-ASCII content. The reproduced CRLF and
  U+2028 failure reaches the embedding provider without a chunking panic
  (#1100, related #1098).
- Unknown Streamable HTTP session IDs return `404`, allowing conforming MCP
  clients to initialize a fresh session after a server restart.
- Bundle startup logs redact generated MCP registration values and omit the
  raw registration response.
- API and bundle release builds use a 64 MiB rustc worker-thread stack, meeting
  the Rust 1.92 thin-LTO requirement reported by the hosted release build while
  preserving locked dependencies.

## Internal hosted foundation

This release includes feature-gated internal work for forced-RLS tenant scope,
separate PostgreSQL migration/runtime roles, durable authorization audit, AWS
KMS-backed user connection material, Redis request admission, controlled
outbound inference, and account-scoped circuit breakers. Community Edition
remains the default public path. Hosted routes require an internal
feature-enabled build and deployment-specific PostgreSQL, Redis, KMS,
identity, malware-scanning, destination-policy, and receipt evidence.

This is not an unqualified hosted-readiness, complete-backup, portability, or
suite-parity claim. Encrypted user connection material requires the matching
KMS custody and trusted tenant/user/row context in addition to a verified
database restore. Tenant plan/billing integration and remaining live
provider/KMS receipts are separate launch gates. Knowledge Shard claims for
this release are limited to the `core-v1` application contract.

## Upgrade

```bash
docker compose -f docker-compose.bundle.yml pull
docker compose -f docker-compose.bundle.yml up -d
```

The release contains six forward migrations, `20260824010000` through
`20260824010500`, which normal startup applies automatically. Take and verify a
pre-upgrade database backup first. For rollback, stop writes and restore that
snapshot to a separate destination before starting the prior known-good
release; do not run destructive down SQL, disable RLS, or grant `BYPASSRLS` to
the runtime role.

After upgrade, retry one note that previously remained at `Chunking content...`
with CRLF/non-ASCII input. Confirm the embedding job completes or reaches a
bounded retry/terminal-failure state. Keep diagnostic captures private and
share only the outcome publicly.
