# v2026.7.20 Release Announcement

Fortemi v2026.7.20 prevents background embedding and extraction jobs from
remaining in `running` indefinitely when a handler never resolves, panics, is
cancelled, or loses its final state update. This patch does not change the
database schema or Knowledge Shard contracts and does not require a queue
reset.

## Fixed

- Every job handler is bounded by the configured `JOB_TIMEOUT_SECS` and moves
  through finite delayed retries to a terminal failure when necessary.
- Handler panics and abnormal task termination are contained with stable,
  redacted `poison` / `handler_panicked` evidence. Panic payloads and note
  content are never logged or persisted.
- Stranded `running` jobs are recovered both at worker startup and by an
  independent periodic sweep. The stale threshold is twice the effective
  runtime job timeout and the transactional reaper remains safe across
  multiple workers.
- `h2` is updated to 0.4.16 to resolve `RUSTSEC-2026-0258`.

## Diagnostics

Set `FORTEMI_DIAGNOSTIC_PROFILE=jobs` to collect targeted JSON job-stage
telemetry with ANSI disabled. Explicit `RUST_LOG`, `LOG_FORMAT`, `LOG_FILE`,
and `LOG_ANSI` values continue to override the profile defaults. The bundle
also forwards `JOB_STALE_REAP_INTERVAL_SECS`.

Diagnostic records contain only opaque per-run correlation tokens, stage
names, counts, lengths, durations, limits, and stable reason codes. Keep the
capture private for support review and never post it publicly.

## Upgrade

```bash
docker compose -f docker-compose.bundle.yml pull
docker compose -f docker-compose.bundle.yml up -d
```

No destructive database reset, queue deletion, or migration command is
required. After upgrade, reproduce one note that previously remained in
`running` and confirm it completes or reaches a bounded retry/failure state.
