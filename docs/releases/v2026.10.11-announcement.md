# Fortémi 2026.10.11

The global rate limiter now sustains the configured requests per period while
preserving burst capacity: 600 requests per 60 seconds refills one request every
100ms. Fractional nanoseconds round up; unrepresentable quotas fail startup.
If using the temporary old-binary workaround `RATE_LIMIT_PERIOD_SECS=1`,
restore `RATE_LIMIT_PERIOD_SECS=60` atomically with the corrected binary rollout;
leaving `1` would permit 600 requests/second.

Note profile similarity now keeps roots and candidates within the selected tenant archive. Hidden and deleted notes and ineligible embedding sets remain excluded. Imported profile vectors can participate without auxiliary embedding-set memberships.

Graph reads through `GET /api/v1/graph/{id}` use the verified tenant/archive
connection for admission and traversal. Missing or foreign roots return 404
after authorization, and denied roles retain 403. This completes the graph GET
portion of #1280; other closed routes retain their admission rules.

Embedding-import status stays readable while a run is applying. Duplicate active
run IDs return 409, applied replay remains supported, and corrupt completed
reports remain errors (#1313). Durable interruption recovery is tracked
separately in #1314.

fortemi-login scopes saved sessions to the complete issuer URL and client ID, refuses mismatched legacy sessions, and requires explicit opt-in for plaintext file fallback.

Builds reuse compatible Cargo state with ownership checks, stable CI identity and bounded retention. Docker compiler caches separate image families and architectures, including hosted builds. Compiler reuse requires compatible builder storage to survive; removing a temporary builder leaves its next compilation cold. Docker-only CI jobs no longer allocate unused host Cargo entries, and ordinary tests avoid unconsumed coverage instrumentation.

This release changes no database migration, protocol or shard schema. Existing
named-profile compatibility limits remain in effect.
