# Fortemi 2026.10.14

This patch corrects hosted role-based authorization for routes that were marked
for backing-resource normalization but denied every caller. Note-scoped
concepts and provenance reads now authorize like the note itself, which restores
the HotM graph view. Archive job control, note move, user enable/disable, backup
files, per-archive backup, embedding configs, and event and ingest tokens now
resolve their backing resources and fail closed. Moving a note refuses a target
collection outside the note's archive, and purging a note outside the public
archive now works.

Partial knowledge-shard imports that reference an unavailable destination note
receive HTTP 400 before graph writes, rather than an internal server error.
Entity-addressed similarity requests accept numeric `k`, such as `k=40`, with
the same defaults, limits, filtering and validation as note-addressed requests.

The bundle and test database images pin PostGIS 3.6.4, which matches their
PostgreSQL 18.4 base. A newer PostGIS build had begun to install that could not
load on 18.4. Dependency updates address RUSTSEC-2026-0436 (`calamine`),
RUSTSEC-2026-0538 (`quinn-udp`) and RUSTSEC-2026-0486 (`rustix`), and
record reviewed, expiring exceptions for an unbuilt `libsqlite3-sys` advisory
and the unmaintained `pin-utils` crate.

Version 2026.10.13 was prepared but never tagged or published, so its changes
ship in this release. The workspace, MCP, Helm and AsyncAPI versions advance to
2026.10.14. The v2026.10.12 tag, whose immutable publication failed, remains
unchanged.

Existing named-profile compatibility limits and interrupted-import recovery
tracking (#1314) continue to apply.
