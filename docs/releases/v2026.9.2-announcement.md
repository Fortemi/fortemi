# v2026.9.2 Release Announcement

Fortemi v2026.9.2 adds a bounded, versioned MCP dataset execution surface for
callers that need more than a single import request. The new lifecycle composes
Fortemi's existing atomic source-addressed upsert contract without turning MCP,
Knowledge Shard transfer, and live persistence into one schema.

## Versioned dataset execution

The core MCP tool `manage_dataset_execution` advertises an alpha
live-remote-persistence capability and supports:

- `capabilities` for the exact contract, schema, profile, and resource limits;
- `preview` for pure fail-closed negotiation with visible optional fallback;
- `execute` for one UUID-scoped atomic source-upsert batch;
- `status`, `checkpoint`, `cancel`, and exact-content `resume` or `retry`;
- `verify` for detached canonical `RunReceipt` verification; and
- `archive` for bounded, namespace-scoped soft deletion.

Requests bind the runtime version, source revision, execution mode,
destination, schema digests, and indexing, retrieval, and lineage profiles.
Exact replay returns the same receipt. Reusing a run UUID with different
canonical content fails closed.

## Resource and cleanup boundaries

The alpha profile accepts at most 500 records, 16 MiB total input, 4 MiB per
record, 120 seconds per operation, one concurrent operation, traversal depth
8, and 1,000 results. It performs no outbound network access. Only fail-fast
rejection without reconciliation is supported in this revision.

Execution and archive deadlines keep the runtime alive until the bounded
operation resolves. If transport is interrupted, the receipt reports an
ambiguous outcome and directs an exact-content retry against the durable
journal. If archive reaches its deadline, it reports `ARCHIVE_TIMEOUT` and
hashed unresolved identifiers; it never enumerates or purges another dataset
namespace.

## Receipts and contract evidence

`contracts/dataset-execution/1.0.0` publishes strict request and `RunReceipt`
schemas, authority metadata, canonical JSON and SHA-256 rules, positive and
negative fixtures, lifecycle vectors, and an independent verifier. Receipts
omit source content and raw logical identifiers while retaining canonical
digests, bounded effect counts, selected profiles, checkpoints, degradation,
and stable reason codes.

## Compatibility boundary

This release qualifies only the alpha live-remote-persistence dataset profile.
It does not establish full suite parity, complete backup, or universal
portability. Dataset execution is not a Knowledge Shard `core-v1`, `record-v1`,
or `full-v1` capability, and the AIWG-to-shard converter remains an explicit
bridge rather than a shared schema.

Broader transportability gaps remain tracked separately in the suite issue
plan. The versioned MCP negotiation, lifecycle, and receipt follow-ups are
tracked in Fortemi #1129, #1130, and #1131; downstream AIWG adoption remains
tracked in roctinam/aiwg #2242.

## Upgrade

Use the signed `v2026.9.2` release and its published checksums. Existing REST
and MCP operations remain available. Callers should discover the descriptor,
preview each plan, require the exact advertised profiles and limits, and retain
the redacted receipt for replay and audit evidence.
