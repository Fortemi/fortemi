# Fortemi 2026.11.1

This release fixes slow full-text search. Lexical candidate selection now uses
the database's GIN indexes instead of re-parsing every note's title, content and
attachment text at query time. On a production memory, a search that took 42
seconds now completes in milliseconds. Results, tenant isolation, archive
scoping, tag filters and ordering are unchanged.

Cross-memory federated search (`POST /api/v1/search/federated`) had the same
problem and is fixed the same way: each memory now uses an index-backed union of
the stored text-search vector and a title expression.

Four new migrations add the supporting indexes: `idx_note_title_tsv_english` for
note titles and `idx_attachment_extracted_fts_english` and
`idx_attachment_extracted_fts_simple` for attachment text. The three
public-schema builds run `CONCURRENTLY`; the fourth adds the same indexes to
existing archive schemas with plain `CREATE INDEX`, and new archives receive
them when created.

Upgrade notes:

- After upgrading, check that the three concurrent indexes are valid. A failed
  concurrent build can leave an invalid index that `IF NOT EXISTS` will not
  repair. Query `pg_index` for `indisvalid` on those index names, and `DROP
  INDEX` and re-run any that are invalid. The exact query is in the CHANGELOG.
- The archive-schema migration blocks writes to archive tables briefly while the
  indexes build. It is a one-time startup cost; schedule the upgrade
  accordingly.

Known limitations: a plain multi-word query must match within a single unit
(title, current content or one attachment), while explicit `AND` matches across
units. Trigram and bigram strategies have no index on attachment text, so that
arm still scans attachments.

The workspace, MCP, Helm and AsyncAPI versions advance to 2026.11.1. The last
published release before this one is v2026.10.14.
