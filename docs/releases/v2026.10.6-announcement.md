# Fortémi 2026.10.6

2026.10.6 completes external-OIDC single-tenant mode. The configured tenant
owns all content, identities, memories and jobs. The API runs as a restricted
database role under forced row-level security. Archive management needs
`admin`, and readers get archive-filtered live events and a reader archive
picker. It consumes fortemi-auth 2026.10.3.

**Upgrading an external-OIDC deployment from 2026.10.5 is an offline upgrade.**
Read [Upgrade notes](#upgrade-notes) before you start.

## What changed since 2026.10.5

- **Configured tenant owns everything (#1205).** In external-OIDC single-tenant
  mode, `FORTEMI_AUTH_DEFAULT_TENANT` is the canonical owner. On first start,
  the server moves existing local-tenant rows to that owner in one atomic,
  idempotent transaction and records a completion receipt in
  `public.external_oidc_ownership`. UUIDs, attachment bytes, PAT hashes and
  customized settings are kept.
- **Restricted runtime database role (#1205, #1220).** External-OIDC and hosted
  modes need a migration owner with BYPASSRLS (`MIGRATION_DATABASE_URL`) and a
  separate `NOSUPERUSER NOBYPASSRLS` runtime login (`DATABASE_URL`). The
  all-in-one bundle provisions this split itself when neither URL is set: it
  creates `fortemi_runtime` once, rotates its password on every start and keeps
  the tenant registry read-only and audit events append-only for it.
- **Archive management requires `admin` (#1201).** Updating, deleting, cloning
  and setting the default archive, and the statistics overview
  `GET /api/v1/memories/overview`, now require `admin` in external-OIDC mode.
  Readers use the new read-scoped `GET /api/v1/memories/available`, which
  returns names and default flags only. Archive visibility applies to routing,
  jobs, inventories, ingest tokens and live and replayed events; hidden and
  missing archives both return 404. The default policy still allows every
  archive in the tenant; per-archive grants are enterprise work
  (`Fortemi-Enterprise/rbac#2`).
- **Read-scoped live events (#1204).** Credentials with `read` can open
  archive-filtered SSE streams; `mcp` still works for service clients. Live
  delivery and `Last-Event-ID` replay use the same archive and tenant filters.
  Envelopes add `archive_name` and `archive_schema` and keep the legacy `memory`
  field; in external-OIDC single-tenant mode they carry the verified
  `tenant_id`. Streams end at the credential's expiry.
- **Identity in `/api/v1/me` (#1206, #1207).** `/me` returns the verified
  `tenant_id`, the token's authorized party (`azp`), and the optional `email`
  and `email_verified` claims. Email is attribution only, never authority.
- **Compatibility discovery (#1203).** `GET /api/v1/system/compatibility`
  reports `external_oidc` mode with the trusted issuer, accepted resources, the
  verifier claim contract (4.0.0, `rust-node-jwt-v1`) and local OAuth
  disablement. Consumers that do not support `external_oidc` keep failing
  closed for that mode.
- **Search (#1217, #1219).** External embedding sets apply their
  `query_template` to queries on every provider path, store an effective
  dimension separate from the provider's raw dimension, and L2-normalize
  truncated vectors. MMR diversity ordering now survives chain deduplication.
- **Dependencies.** rustls 0.23.46 for RUSTSEC-2026-0346 to RUSTSEC-2026-0349.
- **Supply chain (#1221).** Upstream yanked the `zip` 2.4.2 and 3.0.0 releases
  this build uses; cargo-deny allows those two versions until 2026-10-31 while
  calamine and utoipa-swagger-ui move to `zip` 9. Fortemi reads archive entries
  only in memory. Swagger UI is now built from the checksum-pinned vendored
  archive instead of a GitHub download.

## Upgrade notes

Community (local auth) deployments need no changes.

For external-OIDC deployments, follow
[External OIDC canonical ownership upgrade](../content/external-oidc-upgrade.md).
In short:

1. Back up PostgreSQL and attachment storage, and record the configured tenant
   UUID.
2. Make sure your identity provider grants `admin` to administrators. `write`
   alone no longer manages archives.
3. Point reader clients that used `/memories/overview` at
   `/memories/available`.
4. Stop every API instance and worker that writes the database. Rolling
   upgrades across the ownership boundary are not supported.
5. Bundle deployments that set neither `DATABASE_URL` nor
   `MIGRATION_DATABASE_URL`: update the image only; the bundle provisions both
   database roles. Every other deployment, including a bundle with either URL
   set, must set both: `MIGRATION_DATABASE_URL` (table owner with BYPASSRLS)
   and `DATABASE_URL` (`fortemi_runtime`, no BYPASSRLS), prepared as in the
   guide. Startup fails if one is missing.
6. Start one instance, wait for readiness, check
   `SELECT owner, completed_at FROM public.external_oidc_ownership;`, then start
   the rest.

After a successful upgrade, rolling back to 2026.10.5 requires restoring the
backup.

## Knowledge Shard schema 2.2.0

This release can write Knowledge Shard schema 2.2.0 (`full-v1` profile). That
schema adds optional `query_template`, `vector_source` and `provider_dimension`
fields. A `full-v1` export selects 2.2.0 only when it contains one of them;
otherwise schema selection is unchanged (1.2.0 for the default `core-v1`
profile, 2.0.0 or 2.1.0 for `full-v1`). Requesting an older schema for an export
that contains these fields fails instead of dropping them. Schema 2.2.0 itself
remains an **unreleased candidate** until its consumers qualify it
(Fortemi/fortemi-react#476, Fortemi/HotM#323, roctinam/aiwg#3157). The
contract requires a consumer that has not qualified 2.2.0 to reject it before
writing anything.

## Images

All release images are published as `linux/amd64` + `linux/arm64` indexes:

- `ghcr.io/fortemi/fortemi:2026.10.6`
- `ghcr.io/fortemi/fortemi:bundle-2026.10.6`
- `ghcr.io/fortemi/fortemi-mcp:2026.10.6`
- `ghcr.io/fortemi/fortemi:2026.10.6-hosted`

Verify the published digest with the release public key from the signed source
tree:

```bash
PUB=docs/security/cosign.pub
REF=ghcr.io/fortemi/fortemi@<digest published with the release>
cosign verify --key "$PUB" --insecure-ignore-tlog=true "$REF"
cosign verify-attestation --key "$PUB" --insecure-ignore-tlog=true \
  --type spdxjson "$REF" >/dev/null
cosign verify-attestation --key "$PUB" --insecure-ignore-tlog=true \
  --type slsaprovenance1 "$REF" >/dev/null
```
