# v2026.7.13 Release Announcement

Fortemi v2026.7.13 delivers the receipt-bound Knowledge Shard schema 2
authority and the supported-platform server-to-consumer conformance workflow.

## Highlights

- Exact `2.0.0/full-v1` import and opt-in export preserve required component
  presence and attachment bytes through clean repeated round trips.
  `1.2.0/core-v1` remains the default export. Schema 2 `core-v1` and
  `record-v1` are not advertised.
- Fortemi-owned run 6393 passed the declared authority-to-React/core-to-HotM
  contract surface on Linux x86_64, Linux arm64, and native macOS arm64 at
  the receipt-bound revisions.
- Native Linux arm64 sidecars are published with checksum-bound provenance for
  the supported-platform consumer journey.
- Attachment-sidecar recovery now uses durable journals, bounded staging, and
  clean retry convergence after process aborts.

## Compatibility Boundary

The platform result is scoped to exact `2.0.0/full-v1` and the participant
revisions recorded by run 6393. Windows validation is deferred to Fortemi
issue #1096. The evidence does not establish portability beyond those three
cells, recovery of product state outside the exact archive profile, launched
desktop GUI or native-dialog coverage, power-loss durability, or one schema
shared by the AIWG static index, Knowledge Shard transfer, and live Fortemi
persistence planes.

The broader suite audit in issue #1081 remains `NO-GO` pending independent
acceptance.

## Upgrade Notes

Consumers should continue requesting `1.2.0/core-v1` unless they require and
can validate the complete `2.0.0/full-v1` contract. Deployments that consume
native sidecars should retain the immutable release tag and checksum receipt
used for each platform.
