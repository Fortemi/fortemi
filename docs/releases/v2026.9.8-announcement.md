# Fortémi 2026.9.8

Hosted note creation, authorization and realtime delivery now consistently follow the authenticated tenant. This patch prevents cross-tenant object access and event delivery while preserving same-tenant operations.

The source also includes the opt-in OpenBao Transit key provider. Internal hosted builds explicitly enable `hosted-auth,kms-vault` and configure independent CA trust, a protected renewable token file and pre-provisioned derived Transit keys. The provider binds the tenant, user, resource, purpose and schema to encryption, reloads credentials per request and supports same-DEK rewrap after operator key rotation.

Standard public images and native binaries retain their existing feature profiles; they do not gain an enabled OpenBao provider. Deploy the separately qualified internal hosted build when using OpenBao. Disposable-provider tests and the isolated Lane A receipts have distinct scopes; neither establishes general hosted availability or suite portability.

See the OpenBao KMS guide for configuration and operational requirements. Release completion requires the source validation, container publication, comprehensive tests, native binaries and mirror checks to pass.
