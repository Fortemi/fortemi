# Fortémi 2026.10.5

2026.10.5 makes the shipped Keycloak reference work as shipped. The reference
realm and claim policy in `deploy/identity/` are now qualified end to end
against Keycloak 26.7.3 in CI. See the
[2026.10.2 announcement](v2026.10.2-announcement.md) for the features and
upgrade notes of this server line.

## What changed since 2026.10.4

- **Claim-policy example loads.** `deploy/identity/claim-policy.example.json`
  carried a `$schema` key that the strict policy loader rejects, so a server
  started from the example did not come up (#1200). The key is removed.
- **Keycloak key sets are accepted.** With fortemi-auth 2026.10.2 the verifier
  ignores JWKS entries it cannot use, such as Keycloak's RSA-OAEP encryption
  key, instead of rejecting the whole key set. 2026.10.4 answered 503
  (`authentication authority is temporarily unavailable`) against a default
  Keycloak realm.
- **Advertised scope names work at the identity provider.** MCP clients request
  the scope names Fortémi advertises (`read`, `write`, `admin`, `mcp`). The
  reference realm now defines them as optional scopes that grant nothing, so
  Keycloak no longer answers `invalid_scope`. Authority still comes only from
  client roles mapped by the claim policy and capped per client.
- **Path-form resource metadata.** In external OIDC mode the API serves RFC 9728
  metadata at `/.well-known/oauth-protected-resource/<resource path>` for a
  configured audience on the server's own origin, matched on the raw request
  path. An audience with a query string, or one that shares its path with
  another audience, has no path-form document (404).
- **`MCP_HOST`.** Optional bind address for the MCP HTTP server. The default
  (all interfaces) is unchanged.
- **Dependencies.** `quinn-proto` 0.11.19 for RUSTSEC-2026-0338 to
  RUSTSEC-2026-0342.

## Upgrade notes

Upgrading from 2026.10.2, 2026.10.3 or 2026.10.4 needs no configuration
changes unless you use the earlier reference examples:

If you imported the earlier reference realm, add the four optional scopes
`read`, `write`, `admin` and `mcp` (no mappers, no role mappings) to your
interactive clients, or re-import `deploy/identity/keycloak/realm-example.json`
into a new realm. If you copied the earlier claim-policy example, delete its
`$schema` line.

## Images

All release images are published as `linux/amd64` + `linux/arm64` indexes:

- `ghcr.io/fortemi/fortemi:2026.10.5`
- `ghcr.io/fortemi/fortemi:bundle-2026.10.5`
- `ghcr.io/fortemi/fortemi-mcp:2026.10.5`
- `ghcr.io/fortemi/fortemi:2026.10.5-hosted`

Verify the published digest with the release public key from the signed source
tree:

```bash
PUB=docs/security/cosign.pub
REF=ghcr.io/fortemi/fortemi@<digest published with the release>
cosign verify --key "$PUB" --insecure-ignore-tlog=true "$REF"
cosign verify-attestation --key "$PUB" --insecure-ignore-tlog=true \
  --type spdxjson "$REF" >/dev/null
cosign verify-attestation --key "$PUB" --insecure-ignore-tlog=true \
  --type slsaprovenance1 "$REF" >/dev/null
```
