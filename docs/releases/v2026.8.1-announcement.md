# v2026.8.1 Release Announcement

Fortemi v2026.8.1 ships the operational and contract hardening completed since
v2026.8.0. It makes archive lifecycle tests deterministic, aligns extraction
strategy storage with the runtime model, strengthens bundle backup and PKE
validation, and publishes the typed SNN retention-safety response consumed by
HotM.

This is also the first Fortemi application release under the release-only
container policy. Ordinary pushes validate code and contracts but do not
publish container versions. The signed CalVer tag starts the release build and
publishes only the stable version and documented stable aliases.

## Archive and recovery reliability

- Archive create, clone, sync, and drop operations now share a
  transaction-scoped PostgreSQL database lock. The full-workspace clone race in
  #1122 is covered by a deterministic lock-wait regression, and the existing
  class-and-length-only database error redaction remains unchanged.
- Bundle backup and pre-migration snapshot paths use bundle-local
  administrative dumps and validate recovery prerequisites before mutation.
- PKE inputs are validated before dispatch; sensitive values and raw
  database diagnostics remain outside responses and logs.

## Fortemi contract updates

- The canonical OpenAPI document now exposes the complete SNN result and the
  explicit `allow_aggressive_pruning` input. Unsafe plans return the typed
  safety result instead of being represented as a successful prune.
- HotM already consumes this exact schema and keeps aggressive pruning behind
  an explicit operator decision. The release pairing still reports OpenAPI,
  AsyncAPI, compatibility, authentication, and Knowledge Shard gates
  independently.
- Knowledge Shard evidence is unchanged. Support remains limited to the exact
  schema/profile/producer/consumer tuples enumerated in the Fortemi contract
  registry and their immutable receipts.

## CI and supply-chain behavior

- Chained workflows check out the verified source commit rather than a moving
  branch, closing the provenance gap tracked by #1124.
- Main and feature pushes no longer publish Fortemi or bundle container tags.
  Publication occurs only from the signed CalVer release flow.
- CI network allocation and the GPU Ollama host gateway are explicit and
  run-scoped, reducing interference between concurrent validation jobs.

## Upgrade

```bash
docker compose -f docker-compose.bundle.yml pull
docker compose -f docker-compose.bundle.yml up -d
```

The release adds forward migration `20260828190000`, which adds the canonical
`archive`, `spreadsheet`, and `email` attachment extraction-strategy values if
they are absent. PostgreSQL applies the enum additions idempotently. Back up the
database before upgrading and restore that snapshot to a separate destination
if rollback is required; do not attempt destructive enum reversal in place.

After upgrading, verify one archive clone, one bundle snapshot, and one
attachment using each newly recognized extraction strategy. For graph
maintenance, run SNN in dry-run mode first and review the retention-safety
result before authorizing any aggressive-pruning override.
