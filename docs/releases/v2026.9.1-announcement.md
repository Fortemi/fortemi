# v2026.9.1 Release Announcement

Fortemi v2026.9.1 adds an authority-owned contract for importing notes from
externally managed systems without composing ordinary create and update calls.
The new operation is atomic, replay-safe, and deliberately separate from
Knowledge Shard state transfer.

## Source-addressed note upsert

`POST /api/v1/notes/source-upsert` and the core MCP tool
`upsert_external_notes` implement `source-note-upsert/1.0.0`.

- The server derives tenant and memory from verified request state.
- Each item is addressed by a source namespace and external ID within that
  scope.
- Batches contain 1–500 items and commit notes, originals, revisions,
  activities, source identities, and the import journal in one transaction.
- Exact content replay returns `unchanged`; exact batch replay returns the
  prior note identities without adding rows.
- Changed content follows an explicit `version`, `replace`, or `conflict`
  policy. The default is `version`.
- Dry-run and rejected requests make no persistent changes.

The response exposes an opaque SHA-256 external-identity hash rather than the
raw external ID. Optional caller-stable UUIDs can select the note identity only
on first insert and cannot retarget an existing source identity.

## Isolation and operational safety

Hosted writes remain inside the transaction-scoped tenant boundary and forced
PostgreSQL RLS. Unexpected failures roll back the whole batch. Validation,
conflict, and replay paths do not enqueue jobs, write blobs, publish outbox
events, or leave partial import journals.

Debug output, activity metadata, responses, and journals omit raw external
keys and imported content. Receipts contain bounded counts, stable reason
codes, note UUIDs, and content or identity digests.

## Other corrections

- Native sidecar builds and rolling publication now run only for release tags.
- Release-aligned MCP UAT covers manual-note-link create/replay and the
  canonical tag-path grammar without echoing rejected input.

## Compatibility boundary

Source identities belong to Fortemi's live persistence plane. They are not
added to Knowledge Shard `core-v1`, `record-v1`, or `full-v1`. When a
selected memory contains source identities, Knowledge Shard export reports the
typed loss code `source-identity-outside-profile`.

The existing receipt-bound Knowledge Shard and supported-platform results
remain valid only for the exact revisions they name. This release does not
claim universal portability or one shared schema. It does not claim complete
backup or current-head suite conformance.

## Upgrade

Use the signed `v2026.9.1` release and its published checksums. Apply the
additive source-identity migration before enabling callers. Rollback first
disables the route and its callers; preserve live source identity and import
journal state separately before removing the new tables.
