# Fortémi 2026.10.2

> **Version note.** 2026.10.1 published its images and release assets, but image
> signing failed partway through. The OpenBao token used by the signing step
> expired after five minutes. That release was not finalized, and its images are
> unsigned. 2026.10.2 is the signed correction. It contains everything in
> 2026.10.1, plus the changes below.

Fortémi 2026.10.2 adds two things:

- **External embeddings (R1).** Fortemi can now store, search and import
  embeddings produced outside it, at any dimension. Index builds no longer block
  ingest.
- **End-user identity through your own OIDC provider (ADR-110).** The API and
  MCP server act as resource servers for an external identity provider, such as
  a Keycloak realm. Every request is attributed to a real user. Users can sign
  in from the CLI, from MCP clients and from scripts, without a shared API key.

## Highlights

### Identity and access

- **External OIDC mode** (`FORTEMI_AUTH_MODE=external-oidc`, #1190):
  - IdP-issued JWTs protect the whole API outside hosted multi-tenancy;
  - each service accepts only its exact resource audience (`https://host` for
    the API, `https://host/mcp` for MCP);
  - groups and roles map to Fortemi scopes through the claim policy.
- **User principals** (#1191):
  - users are provisioned just-in-time from the token's `(iss, sub)`, never
    from email;
  - notes, background jobs and embedding imports are attributed to the user who
    caused them;
  - `GET /api/v1/me`, the MCP `whoami` tool, and admin endpoints to disable and
    enable users.
- **Personal access tokens** (`mm_pat_`, #1192): a signed-in user can mint an
  expiring, scope-limited token for tools that cannot run an OAuth flow.
  - It is shown once and stored only as a keyed HMAC.
  - On every use it is capped at the user's current scopes.
  - Disabling the user revokes their tokens.
- **Truthful discovery** (#1194):
  - protected-resource metadata names your identity provider;
  - a `401` carries `WWW-Authenticate` with the metadata URL;
  - a scope-based `403` returns `insufficient_scope`.
  
  An MCP client with no prior configuration can find the right authorization
  server.
- **Client onboarding** (#1196):
  - a reference Keycloak 26.7 realm, with pre-registered Claude Code, Claude
    Desktop, Cursor and VS Code clients;
  - a public `fortemi-cli` client (loopback PKCE and device grant);
  - the `fortemi-login` sign-in helper;
  - a [connection guide](../content/connect.md).
- **MCP sessions** (#1193):
  - sessions are bound to the verified principal;
  - every request uses its own bearer token;
  - user requests never fall back to the server's API key.
- **Bearer front door** (#1197):
  - Helm and Kustomize route `/api/*`, `/mcp` and the protected-resource
    metadata straight to the services, with optional Istio JWT checks;
  - the API rate-limits failed authentication per client IP and rejects
    oversized `Authorization` headers.
- **Local authorization server hardening** (#1189, #1195):
  - redirect URIs are parsed before the loopback-port exception applies;
  - dynamic registration rejects unsafe redirect metadata;
  - the local server fails closed when an external IdP is configured.

### Embeddings (R1)

- **Configurable dimensions and `halfvec` storage** (#1175), with Knowledge
  Shard `2.1.0`.
- **Asynchronous shape-keyed HNSW indexes** (#1175, #1181), built by
  background jobs. Bulk loads can defer the build (`defer_index_build`) and
  trigger it afterwards (`POST /api/v1/embedding-sets/{id}/build-index`).
- **Set-scoped re-embedding** (#1182): other sets and externally managed sets
  are never touched.
- **Embedding space contract** (`space_contract` / `space_id`, #1174).
- **Entity profile vectors and similarity search** (#1183):
  `/api/v1/notes/{id}/similar`, `/api/v1/entities/similar` and the MCP tool
  `find_similar_entities`.
- **External embedding run imports** (#1177):
  - entity-keyed NDJSON uploads with a checksummed manifest, ordering,
    idempotency, deletions and per-row rejections;
  - Parquet converts through `scripts/vector-import/parquet_to_ndjson.py`.
- **Index operations** (#1181):
  - a per-set `ef_search`;
  - admin `GET /api/v1/embedding-sets/{slug}/index-health` with an optional
    recall probe;
  - automatic `ANALYZE` after large imports;
  - a recall acceptance test. Measured recall@10 is 1.000 at 10k and 0.983 at
    100k vectors (1024-dim, default `ef_search`).

## Upgrade notes

1. **Back up first.** This release adds several migrations and replaces the
   HNSW indexes.
2. **Index rebuild after upgrade.** Migrations drop the old per-set HNSW indexes
   and queue `build_set_index` jobs for the new shape indexes.
   - Until those jobs finish, semantic search still works but uses a sequential
     scan, which is slower on large archives.
   - Check progress with `GET /api/v1/embedding-sets/{slug}/index-health`.
   - See `docs/content/vector-index-operations.md` for `maintenance_work_mem`
     and parallel worker guidance.
3. **Local OAuth server with an external IdP now fails closed.** If
   `FORTEMI_AUTH_ISSUER` (or hosted OIDC) is configured and you still rely on
   Fortemi's own `/oauth/*` server, startup refuses.
   - To keep the local server, set `FORTEMI_OAUTH_ALLOW_LOCAL_AS=true` and
     configure authenticated owner consent.
   - Deployments without an external IdP are unaffected.
4. **External OIDC mode needs these settings:**
   - `FORTEMI_AUTH_MODE=external-oidc`;
   - `FORTEMI_AUTH_ISSUER`;
   - `FORTEMI_AUTH_AUDIENCES`, the exact resource URIs;
   - `FORTEMI_AUTH_CLAIM_POLICY_FILE`;
   - `FORTEMI_PAT_PEPPER` to enable personal access tokens: at least 32 bytes
     from your secret store. Without it the API starts normally, but PATs stay
     disabled and minting returns 503.
   
   `FORTEMI_PAT_REVALIDATE_DAYS` is optional. See
   `docs/content/authentication.md` and `docs/content/connect.md`.
   
   The Helm chart reads the pepper from
   `personalAccessTokens.pepper.existingSecret`; the hosted profile defaults
   this to `fortemi-pat-pepper`. The Kustomize hosted component reads the same
   Secret. Both references are optional.
5. **External OIDC mode disables legacy tokens.** `mm_at_` and `mm_key_` tokens
   are rejected unless they are explicitly allowed with a scope cap.
6. **Path-based imports are opt-in.** Server-side embedding run folders are
   admin-only and must sit under `FORTEMI_VECTOR_IMPORT_ROOT`.
7. **Front door.** Behind an ingress, set `FORTEMI_TRUSTED_PROXY_CIDRS` to the
   ingress pod range only. Strip client-supplied identity headers at the edge
   (`docs/deployment/front-door.md`).

Docker bundle users who do not configure an external IdP can upgrade in place:
pull `ghcr.io/fortemi/fortemi:bundle-2026.10.2` and restart.

## Images

All release images are published as `linux/amd64` + `linux/arm64` indexes:

- `ghcr.io/fortemi/fortemi:2026.10.2`
- `ghcr.io/fortemi/fortemi:bundle-2026.10.2`
- `ghcr.io/fortemi/fortemi-mcp:2026.10.2`
- `ghcr.io/fortemi/fortemi:2026.10.2-hosted`

Verify the published digest with the release public key from the signed source
tree:

```bash
PUB=docs/security/cosign.pub
REF=ghcr.io/fortemi/fortemi@<digest published with the release>
cosign verify --key "$PUB" --insecure-ignore-tlog=true "$REF"
cosign verify-attestation --key "$PUB" --insecure-ignore-tlog=true \
  --type spdxjson "$REF" >/dev/null
cosign verify-attestation --key "$PUB" --insecure-ignore-tlog=true \
  --type slsaprovenance1 "$REF" >/dev/null
```

The 2026.10.1 images remain published but unsigned. Use 2026.10.2.

## Known issues

- **#1163:** tenant-bound `/api/v1/ws` and `/api/v1/ingest/stream` remain
  open. Hosted mode returns `401` without a valid bearer and `503` with one.
- **#1165 to #1169:** remaining hosted route-qualification gaps. Review
  `docs/deployment/hosted-route-qualification.md` before exposing a hosted
  tenant workflow.
- **#943 and #944:** still open. This release fixes redirect parsing and unsafe
  registration metadata, and fails closed with an external IdP. Hosted browser
  authorization remains disabled.
- **#1198:** release runs can be superseded by later CI runs on the shared
  runner. Releases are cut with `main` frozen until the release finalizes.
