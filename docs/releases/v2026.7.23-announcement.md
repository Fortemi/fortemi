# v2026.7.23 Release Announcement

Fortemi v2026.7.23 fixes a Unicode/line-ending failure that could stop an
embedding job during semantic chunking before any inference request was sent.
It also hardens MCP recovery and sensitive-value redaction, makes release image builds
reliable on the pinned Rust 1.92 toolchain, and carries a bounded internal
hosted foundation.

## Fixed

- Semantic chunking now preserves exact UTF-8 byte spans across LF, CRLF,
  lone-CR, mixed line endings, and non-ASCII content. The reproduced CRLF and
  U+2028 failure reaches the embedding provider without a chunking panic
  (#1100, related #1098).
- Unknown Streamable HTTP session IDs return `404`, allowing conforming MCP
  clients to initialize a fresh session after a server restart.
- Bundle startup logs redact generated MCP registration values and omit the
  raw registration response.
- API and bundle release builds use a 16 MiB rustc worker-thread stack, fixing
  the Rust 1.92 thin-LTO compiler crash seen in CI while preserving locked
  dependencies.

## Internal hosted foundation

This release includes feature-gated internal work for forced-RLS tenant scope,
separate PostgreSQL migration/runtime roles, durable authorization audit, AWS
KMS-backed user connection material, Redis request admission, controlled outbound
inference, and account-scoped circuit breakers. Community Edition remains the
default public path. Hosted routes require an internal feature-enabled build
and deployment-specific PostgreSQL, Redis, KMS, identity, malware-scanning,
destination-policy, and receipt evidence.

This is not an unqualified hosted-readiness, complete-backup, portability, or
suite-parity claim. Encrypted user connection material requires the matching KMS custody
and trusted tenant/user/row context in addition to a verified database restore.
Tenant plan/billing integration and remaining live provider/KMS receipts are
separate launch gates. The Knowledge Shard contract is unchanged.

## Upgrade

```bash
docker compose -f docker-compose.bundle.yml pull
docker compose -f docker-compose.bundle.yml up -d
```

The release contains six forward migrations, `20260824010000` through
`20260824010500`, which normal startup applies automatically. Take and verify a
pre-upgrade database backup first. For rollback, stop writes and restore that
snapshot to a separate destination before starting v2026.7.22; do not run
destructive down SQL, disable RLS, or grant `BYPASSRLS` to the runtime role.

After upgrade, retry one note that previously remained at `Chunking content...`
with CRLF/non-ASCII input. Confirm the embedding job completes or reaches a
bounded retry/terminal-failure state. Keep diagnostic captures private and
share only the outcome publicly.
