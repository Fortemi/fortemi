# Fortémi 2026.10.4

> **Version note.** 2026.10.4 publishes the native binaries for the 2026.10.2
> server line. The comprehensive test runs for the 2026.10.2 and 2026.10.3 tags
> failed, so neither published native binary assets. Their container images and
> release entries are valid and signed. See the
> [2026.10.2 announcement](v2026.10.2-announcement.md) for features and upgrade
> notes, which apply unchanged.

## What changed since 2026.10.3

- **MCP scope challenge:** a token without the `mcp` scope now gets a 403 with
  `WWW-Authenticate: Bearer error="insufficient_scope", scope="mcp"`. 2026.10.2
  and 2026.10.3 named `scope="mcp admin"`, which suggests both scopes are
  needed; `mcp` alone is enough.

## Upgrade notes

Upgrading from 2026.10.2 or 2026.10.3 needs no changes. Upgrading from an
earlier version: follow the 2026.10.2 upgrade notes.

## Images

All release images are published as `linux/amd64` + `linux/arm64` indexes:

- `ghcr.io/fortemi/fortemi:2026.10.4`
- `ghcr.io/fortemi/fortemi:bundle-2026.10.4`
- `ghcr.io/fortemi/fortemi-mcp:2026.10.4`
- `ghcr.io/fortemi/fortemi:2026.10.4-hosted`

Verify the published digest with the release public key from the signed source
tree:

```bash
PUB=docs/security/cosign.pub
REF=ghcr.io/fortemi/fortemi@<digest published with the release>
cosign verify --key "$PUB" --insecure-ignore-tlog=true "$REF"
cosign verify-attestation --key "$PUB" --insecure-ignore-tlog=true \
  --type spdxjson "$REF" >/dev/null
cosign verify-attestation --key "$PUB" --insecure-ignore-tlog=true \
  --type slsaprovenance1 "$REF" >/dev/null
```
