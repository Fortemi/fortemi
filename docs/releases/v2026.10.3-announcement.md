# Fortémi 2026.10.3

> **Version note.** 2026.10.3 publishes the native binaries for the 2026.10.2
> server. The 2026.10.2 release's comprehensive test run failed on a test
> fixture, so its native binary assets were never published. Its container
> images and release entries are valid and signed. Server behavior is the same
> as 2026.10.2; see the
> [2026.10.2 announcement](v2026.10.2-announcement.md) for features and
> upgrade notes, which apply unchanged.

## What changed since 2026.10.2

- **Test fixture fix:** the hosted bootstrap-request test now seeds the
  principal's `app_user` row, matching the #1191 note-to-user foreign key.
- **KMS qualification image (Fortemi-Enterprise/kms#4):** a new in-cluster
  test proves the AWS KMS provider under EKS workload identity, and
  `build/Dockerfile.kms-qualification` packages it as a Job image. It is not
  part of the server images.

## Upgrade notes

Upgrading from 2026.10.2 needs no changes. Upgrading from an earlier version:
follow the 2026.10.2 upgrade notes.

## Images

All release images are published as `linux/amd64` + `linux/arm64` indexes:

- `ghcr.io/fortemi/fortemi:2026.10.3`
- `ghcr.io/fortemi/fortemi:bundle-2026.10.3`
- `ghcr.io/fortemi/fortemi-mcp:2026.10.3`
- `ghcr.io/fortemi/fortemi:2026.10.3-hosted`

Verify the published digest with the release public key from the signed source
tree:

```bash
PUB=docs/security/cosign.pub
REF=ghcr.io/fortemi/fortemi@<digest published with the release>
cosign verify --key "$PUB" --insecure-ignore-tlog=true "$REF"
cosign verify-attestation --key "$PUB" --insecure-ignore-tlog=true \
  --type spdxjson "$REF" >/dev/null
cosign verify-attestation --key "$PUB" --insecure-ignore-tlog=true \
  --type slsaprovenance1 "$REF" >/dev/null
```
