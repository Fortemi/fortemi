# v2026.9.4 Release Announcement

Fortemi v2026.9.4 strengthens dataset outcome validation and bulk reprocessing,
and adds configurable tooling for bounded load experiments.

Dataset execution now validates nested requests and receipts against the current
validation authority before attesting success. Uncertain or inconsistent storage
responses retain an ambiguous outcome and withhold the committed checkpoint.
Exact-content retry reconciles the outcome; archive remains unavailable while
that outcome is unresolved.

Bulk reprocessing checks explicit note IDs against live records in the selected
tenant and memory. Deleted, missing and out-of-scope IDs are skipped uniformly;
an empty eligible batch creates no jobs. Operators also get a tested read-only,
tenant-scoped psql recipe.

The new load tooling uses editable JSON defaults, named profiles and explicit
command-line overrides. Rates, windows, repetitions, concurrency, deadlines,
thresholds and budgets can change without source edits. Preflight checks sample
coverage and repeated-run budgets, and binds the effective plan to a new digest.
The experiment lifecycle retains failed attempts, checks telemetry and state,
and verifies cleanup after a settling interval. A local k6 comparison records
its duration-boundary behavior explicitly.

See `scripts/qualification/README.md` for configuration and adapter requirements.
Site-specific values remain explicit selections. The tooling and detached
qualification candidate 2.0.0 do not establish live load capacity, independent
operational observation or consumer admission. Required runtime adapters,
prerequisite receipts and final qualification measurements remain outstanding.

The dataset release remains scoped to alpha `live-remote-persistence`. It adds
no full-suite parity, complete-backup or universal-portability claim, and no new
Knowledge Shard profile guarantee. Use the signed tag and published checksums
when installing or pinning the release.
